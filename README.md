# SAI 동아리방 프론트엔드

SAI 앱 흐름도를 직접 눌러볼 수 있도록 만든 **HTML·CSS·JavaScript 웹 프론트엔드**입니다. 브라우저에서 실행되며, Android APK나 Flutter 프로젝트는 아닙니다. 별도 패키지 설치나 빌드 없이 화면과 버튼, 게이지 이펙트를 확인할 수 있습니다.

## VS Code에서 실행하기

1. ZIP 파일의 압축을 풉니다.
2. VS Code에서 **파일 → 폴더 열기**를 눌러 `sai-room-frontend` 폴더를 엽니다.
3. 확장 프로그램에서 **Live Server**를 설치합니다. 이 프로젝트를 열었을 때 추천 확장으로 표시됩니다.
4. `index.html`을 마우스 오른쪽 버튼으로 누르고 **Open with Live Server**를 선택합니다.
5. 브라우저에서 앱이 열립니다. 휴대폰 모양의 화면 안에서 버튼을 눌러보세요.

`npm install`은 필요하지 않습니다. HTML·CSS·JavaScript 파일을 수정하고 저장하면 Live Server가 변경 내용을 브라우저에 반영합니다.

### 다른 실행 방법

- **가장 간단하게:** 압축을 푼 폴더의 `index.html`을 더블클릭합니다. 로컬 파일로 열었을 때의 데이터 저장 동작은 브라우저에 따라 다를 수 있으므로, 작업할 때는 Live Server를 권장합니다.
- **Python이 설치되어 있다면:** VS Code 터미널에서 프로젝트 폴더를 기준으로 아래 명령을 실행한 뒤 브라우저로 `http://localhost:5500`을 엽니다.

```bash
python -m http.server 5500
```

위 명령은 파일을 브라우저에 전달하는 개발용 서버입니다. 회원 정보나 예약을 처리하는 백엔드는 포함되어 있지 않습니다.

## 눌러볼 수 있는 기능

- [x] 홈: SAI 로고, 인원 게이지, 인원 숫자, 상태 표시와 하단 메뉴
- [x] 예약: 날짜별 타임테이블, 시간 선택, 예약 작성·상세·수정·취소
- [x] 예약 작성: 이용 목적, 예약 주체 이름, 사용 인원 입력과 시간 중복 검사
- [x] 익명게시판: 일반 익명글과 운영진 문의, 글 작성·상세·댓글, 본인 글 수정·삭제
- [x] 커스텀: 기본·물·마그마 게이지와 라이트·다크·블루 테마, 미리보기와 적용
- [x] 설정: 예시 인원과 감지 상태 변경, 저장한 예시 데이터 초기화
- [x] 화면 전환, 버튼 반응, 게이지 애니메이션, 안내 메시지

홈의 인원은 설정에서 바꿀 수 있는 **데모 값**입니다. 기본 게이지 기준은 15명이며, 예약에 입력한 인원은 홈 인원에 합산하지 않습니다. 브라우저나 운영체제에서 동작 줄이기를 사용하면 애니메이션도 줄어듭니다.

## 데이터가 저장되는 곳

작성한 예약·글·댓글과 화면 설정은 현재 브라우저의 `localStorage`에 저장합니다. 저장 키는 `sai-room-frontend-v1`입니다. 새로고침해도 같은 브라우저와 주소에서는 작성한 내용이 유지됩니다.

이 데이터는 다른 회원이나 다른 기기로 전송되지 않습니다. 브라우저 데이터 삭제, 다른 브라우저 사용, 실행 주소 변경 시에는 저장한 내용이 보이지 않을 수 있습니다. 처음 상태로 돌아가려면 앱의 설정에서 데이터 초기화를 사용하세요.

현재 화면에는 실제 로그인, BLE 감지, 회원별 접근 제어, 여러 사용자의 예약 동기화가 연결되어 있지 않습니다. ‘익명’이나 ‘작성자와 운영진만 열람’ 같은 표시는 완성할 앱의 화면 동작을 보여주는 예시이며, 실제 권한 검증은 하지 않습니다. 기능을 확인할 때는 예시 내용을 입력하세요.

## 파일 구성과 수정 방법

| 파일                      | 역할                                | 바꾸고 싶은 내용                   |
| ------------------------- | ----------------------------------- | ---------------------------------- |
| `index.html`              | 앱의 기본 틀과 파일 연결            | 브라우저 제목, 전체 앱 구조        |
| `css/styles.css`          | 색상, 배치, 반응형 화면, 애니메이션 | 글자 크기, 간격, 테마 색상, 이펙트 |
| `js/data.js`              | 초기 예시 데이터                    | 처음 표시할 예약·게시글·설정       |
| `js/app.js`               | 화면 표시와 버튼 동작               | 화면 이동, 입력 처리, 저장 동작    |
| `assets/sai-logo.png`     | 화면에 표시할 SAI 마크              | 로고 교체                          |
| `.vscode/extensions.json` | 추천 VS Code 확장                   | Live Server 추천                   |
| `.vscode/settings.json`   | 프로젝트 실행 설정                  | Live Server 포트                   |

먼저 `css/styles.css`의 색상과 간격을 조금씩 바꿔보면 화면 구조를 익히기 쉽습니다. 예시 데이터를 수정했는데 기존 내용이 계속 보이면 앱 설정에서 데이터를 초기화하세요. 이미 저장된 데이터가 초기 데이터보다 우선하기 때문입니다.

로고 파일을 교체할 때는 같은 파일명과 경로를 유지하면 됩니다. 현재 로고는 제공한 흐름도 이미지에서 가져왔으므로, 이후 원본 로고로 교체하면 더 선명하게 보입니다.

## 나중에 서버를 연결할 때

현재 화면을 유지하면서 아래 부분을 실제 서비스에 연결할 수 있습니다.

1. 예시 사용자 대신 로그인 결과와 회원 권한을 사용합니다.
2. 예약과 게시글을 브라우저 저장소 대신 서버에서 불러오고 저장합니다.
3. 예약 시간 충돌과 글 열람·수정 권한을 서버에서도 검사합니다.
4. 홈의 예시 인원을 실제 비콘 기반 집계 결과로 교체합니다.
5. 운영진 문의와 답변에 실제 계정별 접근 제어를 적용합니다.

지금은 화면과 동작을 검토하는 단계이므로, 프론트엔드를 실행하기 위한 서버 주소나 API 키 설정은 필요하지 않습니다.

## 포함된 글꼴

인터넷 연결 없이 한글을 표시하도록 Noto Sans KR 글꼴을 포함했습니다. 글꼴 라이선스는 `assets/fonts/LICENSE.txt`에서 확인할 수 있습니다.

## 확인한 동작

Chromium에서 예약 생성·수정·중복 시간 차단·취소, 글 작성·수정·삭제·댓글, 문의 접수, 테마 미리보기·적용·새로고침 후 유지, 인원 변경과 초기화를 확인했습니다. 390px·320px 화면과 `index.html` 직접 열기도 점검했습니다.
